# AI Agent 支付安全架构（电商/票务自动购买）

> 来源：用户 2026-06-07 详细讲解。此文档定义 Hermes Agent + 电商/票务插件（淘宝、京东、12306、携程等）自动下单的安全基线。

## 核心原则

AI Agent 自动下单本质 = **工具调用权限 + 平台账号授权 + 支付授权（小额/一次性）**。安全核心：权限最小化、隔离账户、每笔确认、全程日志。

## 一、需要什么权限（3 类核心）

### 1）Agent 自身权限（Hermes/OpenClaw 侧）

| 权限 | 说明 | 推荐设置 |
|------|------|---------|
| 工具调用 | 允许调用浏览器、HTTP 请求、电商/票务插件 | 默认开 |
| 命令执行白名单 | 在 `config.yaml` 限定允许执行的命令 | `allow_browser: true`, `allow_pay: deny` |
| 审批模式 | 每步确认或单次授权 | 新手: `approvals.mode: "on"`, 熟练: `"once"` |

Hermes 相关配置：
```yaml
tools:
  browser: allow
  shell: deny
  pay: deny          # ❗ 核心：禁止自动支付

approvals:
  mode: on           # 每步都要用户确认
  command_allowlist:
    - "curl"
    - "browser open"
```

### 2）平台账号授权（淘宝/12306/携程/外卖等）

- **登录方式**：OAuth 扫码授权，给 Agent 只读 + 下单权限
- **授权范围（Scope）**：只勾「商品搜索、下单、查看订单」，不勾「支付、退款、个人信息修改」
- **各平台情况**：

| 平台 | 对接方式 | 说明 |
|------|---------|------|
| 淘宝/支付宝 | ACT 协议 | 一次指令、一次授权、用完失效，限 1000 元内 |
| 京东 | 浏览器自动化（扫码 Cookie） | 无官方 API，通过 Playwright 模拟 |
| 12306 | 浏览器自动化 | 官方无开放 API，纯浏览器模拟，需扫码登录 |
| 美团/饿了么 | MCP 插件 + OAuth | 下单功能通过插件暴露，OAuth 授权即可 |

### 3）支付权限（最敏感，必须最小化）

**绝对不要给支付密码或免密支付！**

正确做法（三选一可组合）：

1. **一次性授权**：每笔订单 Agent 生成支付链接，用户手动点确认 / 刷脸
2. **小额专用账户**：开空卡 / 余额留几百元，Agent 只能扣这里
3. **平台 AI 付（支付宝）**：委托代办，限额 1000 元，用完自动失效

## 二、操作流程（Hermes 为例，5 步）

```bash
# 1. 安装 MCP 工具
hermes mcp install taobao
hermes mcp install 12306

# ❗ 注意：截至 2026-06，npm 上的 taobao-mcp-demo 是一个空壳包（只注册了 add/sub/mul/div）
# 真正的淘宝 MCP 需要你在淘宝开放平台注册开发者获取 App Key
# 参见 references/jd-anticrawl-debug-log.md 中的详细说明

# 2. 账号授权（只勾「下单」，不勾「支付」）
hermes mcp login taobao

# 3. 配置 config.yaml（安全第一）
#    tools.pay: deny, approvals.mode: on

# 4. 发指令（自然语言）
#    "帮我买明天北京→上海的高铁票，二等座，10 点左右"
#    "帮我在淘宝买一瓶 500ml 矿泉水，价格≤3 元"

# 5. 确认执行
#    Agent 搜索→比价→生成订单→弹窗等你确认→你点「同意」→它下单→你手动支付
```

## 三、安全性（6 条铁律）

### 1）权限最小化（最重要）
- 只给「下单」，不给「支付」；支付永远用户手动
- 只给「只读 + 下单」，不给「改密/提现/退款」
- 不用时关闭工具：`hermes mcp disable taobao`

### 2）账户隔离
- 专用小额支付账户：空卡或余额 ≤500 元，Agent 只能扣这里
- 主账户不放钱，Agent 碰不到

### 3）每笔确认（人工兜底）
- 开启 `approvals.mode: on`，任何下单/支付前必须用户点确认
- ❌ 禁止 `auto_approve: true`

### 4）限额 + 时效
- 单次金额上限：淘宝/支付宝 AI 付 ≤1000 元
- 授权时效：选「单次任务有效，用完自动失效」，不要长期授权

### 5）全程日志 + 可追溯
- Hermes：`hermes --log-level info`，每步记录时间、指令、结果
- 平台侧：订单中心所有 AI 下单标「AI 代买」，可查可退

### 6）不用「无障碍模式」
- OpenClaw 等工具如果要求开系统无障碍权限（能读屏幕、点任何按钮），**绝对不要开**
- 无障碍权限一旦给出，工具能自动输密码、转账、删数据，风险极大

## 四、一句话总结

| 维度 | 内容 |
|------|------|
| 权限 | 工具调用 + 平台下单授权 + 手动支付（绝不自动支付） |
| 操作 | 装插件→扫码授权→开确认模式→发指令→你点确认→手动付钱 |
| 安全 | 最小权限、小额隔离、每笔确认、限时授权、全程日志、不开无障碍 |

## 五、铁律：Hermes 禁止自动下单支付

在当前的 `taobao-jd-pricer` 脚本中：
- 脚本**仅限搜索和读取**，不含任何下单/加购物车/支付的代码逻辑
- 如果要扩展到自动下单，**必须**遵循本文档的安全基线
- 配置必须保持 `tools.pay: deny`，支付永远由用户手动完成
