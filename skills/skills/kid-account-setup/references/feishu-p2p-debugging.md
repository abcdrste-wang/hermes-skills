# 飞书个人版 P2P 私聊调试记录

## 场景

kid（瑞瑞/小白）的飞书 bot 在**群聊功能完全正常**的情况下，**私聊收不到消息**。WebSocket 连接正常（gateway 日志显示 connected），但用户直接给 bot 发私聊消息后，bot 没有任何响应。

## 排查方法论

### 第一步：检查 gateway 日志（最直接）

```
grep -i "chat_type" ~/.hermes-kid/logs/gateway.log
```

- 如果看到 `chat_type=p2p` → 消息已推送到 Hermes，问题在 Hermes 处理链上
- 如果**所有 inbound 消息都是 `chat_type=group`** → **飞书平台没有推送私聊事件**，Hermes 那边查什么都没用

### 第二步：确认群聊正常

群聊能收消息说明：
- ✅ 飞书事件订阅 `im.message.receive_v1` 已勾选
- ✅ App ID/Secret 正确
- ✅ WebSocket 通信正常
- ✅ Hermes message handler 工作正常

群聊和私聊走**同一个事件** `im.message.receive_v1`，群聊能通说明事件订阅配置没问题。

### 第三步：检查 Hermes 代码（确认不是代码层面过滤）

飞书插件关键检查点：

| 位置 | 行号 | 行为 | P2P 影响 |
|------|------|------|---------|
| `_admit()` | ~3967 | `if not is_group: return None` | ✅ 私聊无条件放行 |
| `_handle_message_event_data()` | ~2237+ | 传入 `chat_type` 不做过滤 | ✅ 不区分 p2p/group |
| `_on_p2p_chat_entered()` | grep 定位 | 仅打印 debug 日志 | ✅ 无害（但也没帮助）|

结论：Hermes 代码没有阻止私聊。

### 第四步：确认两个场景的区别

用户说「私聊不了」时，需要确认具体操作方式：

| 场景 | 操作方式 | 飞书平台行为 | Hermes 能否收到 |
|------|---------|-------------|---------------|
| **A** | 飞书联系人中找到 bot → 点进去发消息 | **个人版可能不推送** `im.message.receive_v1` | ❌ 收不到 |
| **B** | 群聊中点 bot 头像 → 弹出会话发消息 | 实际上还是群聊 | ✅ 能收到（chat_type=group） |

## 根因

**飞书个人版（Personal Edition）不将私聊消息推送到 bot 的 WebSocket。** 证据链：

1. Gateway 日志 100% 确认：所有 inbound 消息为 `chat_type=group`，**零 p2p 记录**
2. 群聊和私聊走同一个事件订阅（`im.message.receive_v1`），群聊通说明配置没问题
3. Hermes 代码对 p2p 无条件放行，不存在代码层面过滤
4. 同一台机器、同一个 Hermes 配置，仅飞书账号（组织）不同

## 根因扩展：飞书个人版 vs 团队/企业版

飞书个人版（免费个人账号）和企业版/团队版在 bot 能力上有显著差异：

| 能力 | 个人版 | 团队/企业版 |
|------|--------|------------|
| 群聊中 @bot 回复 | ✅ | ✅ |
| 私聊 bot | ❌ 不推送事件 | ✅ |
| 同一组织多 bot | ❌ 单用户路由冲突 | ✅ |
| 创建团队/组织 | ❌ Web/Mobile 无入口 | ✅ 桌面客户端可创建 |

**重要发现：飞书个人版用户不能私聊 bot，不是配置能解决的。**

## 已知的"无效"方案（别浪费时间）

以下方案看起来合理但实际不解决根因：

1. ❌ 修改 SOUL.md 加上「支持私聊」— 不是 bot 不愿回，是根本没收到消息
2. ❌ 检查 `_admit()` / `_handle_message_event_data()` — 代码没有过滤 p2p
3. ❌ 修改 `FEISHU_REQUIRE_MENTION` — 这是群聊配置，不影响私聊
4. ❌ 重新部署飞书 App — 权限没有问题
5. ❌ 重启 gateway — WebSocket 连接正常
6. ❌ 检查飞书事件订阅 — 群聊能收到说明订阅没问题

## 可行方案

1. **升级免费团队版**：在飞书桌面客户端侧边栏创建团队（免费），将 kid 拉入团队，然后在团队下使用 bot（推荐）
2. **改用群聊方案**：让 kid 在群里 @bot 使用，接受「不支持私聊」的限制
3. **更换平台**：Telegram / Discord 等原生支持私聊的平台（用户已拒绝此方案）

## 确认团队版是否起效

在 kid 的飞书桌面客户端：
1. 点击侧边栏「创建团队」（个人版用户可能需要从侧边栏找创建入口）
2. 团队创建后，将 bot 拉入该团队的群聊或频道
3. 在团队上下文中尝试私聊 bot

如果团队版仍无法私聊，再进一步排查。

## 经验教训

- **gateway 日志是最好的诊断工具**：不要猜，直接看 `chat_type` 字段
- **"WebSocket 连上了"不等于"平台推送了消息"**：连接和事件推送是两个独立链路
- **不要相信用户说的「都试过了」**：用户说的「私聊」有歧义，需要具体确认操作方式
- **不要花时间在 Hermes 配置上排查**：如果 gateway 日志中没有 p2p 消息，问题不在 Hermes 端
